A local web app for managing my own academic reading life: uploading PDFs, tracking what I've actually read, taking notes, building a citation graph, and keeping a research diary — all stored on my own machine rather than in someone else's cloud.

What it does

Papers go in by drag-and-drop, and an AI pass (Groq / Llama 3.3) runs in the background to extract title, authors, year, journal, DOI, and abstract, identify research fields, generate a short summary, and pull out cited references — linking them automatically to anything already in the library. From there, papers move through a reading pipeline (Unread → In Progress → Completed), get organised into colour-coded topics, rated, and annotated with auto-saving notes.

Beyond the library itself: an interactive 3D force-directed reference graph of the whole collection, an analytics dashboard (reading velocity, status breakdown, top fields and authors), a dated research diary with Markdown export and a linked task list, a place to save reading-adjacent videos/playlists/datasets, syntax-highlighted code snippets linked back to papers, and a natural-language question-answering agent over the whole library, grounded in the papers' own summaries and metadata.

Why local

Everything lives in one SQLite database and an uploads folder on disk. No account system, no external server beyond an optional Groq API key for the AI features. Multiple profiles can share one install without their libraries mixing, aside from a shared “Bridging Papers” collection for anything relevant across projects.

Stack

FastAPI + SQLAlchemy + SQLite on the backend, PyMuPDF for PDF parsing, and a vanilla-JS frontend with no build step. The reference graph runs on 3d-force-graph (Three.js/WebGL); code highlighting is Prism.js.
